# 포털 겸용 블로그

GitHub Pages에서 동작하는 Jekyll 블로그입니다. 첫 화면은 포털(프로필과 링크), `/blog`는 블로그입니다.

이 계정의 배포 설정과 기존 사이트 보존 방법은 [GitHub Pages 설정](GITHUB_PAGES_SETUP.md)을 참고하세요. 예시 글과 가상 프로젝트는 제거했습니다.

## 화면 구성

| 주소 | 내용 |
|---|---|
| `/` | 포털: 프로필, 링크, 프로젝트 카드, 최근 글 |
| `/projects/` | 프로젝트 목록과 프로젝트별 관련 글 |
| `/blog/`, `/en/blog/` | 글 목록 (왼쪽에 연도·태그 메뉴) |
| `/tags/` | 태그별 글. 칩을 누르면 그 태그만 보여요 |
| `/search/`, `/en/search/` | 검색. 어디서든 ⌘K (윈도우 Ctrl+K) |

휴대폰(760px 미만)에서는 왼쪽 메뉴가 사라지고 오른쪽 위 메뉴 버튼으로 서랍이 열립니다. 디자인 값(색, 글꼴, 간격)은 `assets/css/main.css` 맨 위 토큰에 모여 있습니다.

## 처음 한 번만 하는 설정

1. GitHub에서 **`username.github.io`** 이름으로 공개 저장소를 만들고, 이 폴더의 파일을 모두 올립니다. (`.github`, `.pages.yml` 같은 점으로 시작하는 파일도 꼭 포함하세요.)
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿉니다.
3. `_config.yml`에서 `title`, `url`, `author`를 내 정보로 바꿉니다. 첫 화면 링크는 `_data/links.yml`, 프로젝트는 `_data/projects.yml`에서 고칩니다. 프로필 사진은 `assets/img/avatar.svg`를 바꾸거나 `author.avatar` 경로를 바꾸세요.
4. 푸시하면 **Actions** 탭에서 배포가 진행되고, 1~2분 뒤 `https://username.github.io`에서 확인할 수 있습니다.

## 글쓰기

**웹에서 쓰기 (추천)**: https://app.pagescms.org 에 GitHub로 로그인하고 저장소를 선택하면 글쓰기 화면이 나옵니다. 이미지와 GIF는 편집 화면에서 바로 올릴 수 있고, 저장하면 자동으로 배포됩니다. 첫 화면 링크도 여기서 고칠 수 있습니다.

**마크다운으로 쓰기**: `_posts` 폴더에 `2026-10-01-글주소.md` 형식으로 파일을 만듭니다. 저장소 페이지에서 `.` 키를 누르면 브라우저 편집기가 열립니다. 글 맨 위 설정은 아래처럼 씁니다.

```yaml
---
title: 글 제목
date: 2026-10-01 09:00:00 +0900
description: 목록과 공유 미리보기에 보이는 한 줄 요약
tags: [태그1, 태그2]
image: /assets/img/대표이미지.png   # 선택: 공유 미리보기 이미지
toc: false                         # 선택: 목차 끄기
comments: false                    # 선택: 댓글 끄기
---
```

날짜가 미래인 글은 그 날짜가 지나고 다시 배포될 때 공개됩니다. 현재는 예시 글 없이 시작하며, `_posts`에 실제 글을 추가하면 됩니다.

## 프로젝트

`_data/projects.yml`(또는 Pages CMS의 **프로젝트** 메뉴)에 적은 순서대로 첫 화면과 `/projects/`에 나옵니다.

- `status`: `live`(운영 중), `dev`(개발 중), `archived`(보관)
- `image`: 스크린샷 경로. 비워 두면 줄무늬 자리표시가 보입니다. 16:9로 잘려 보이니 가로로 긴 화면을 쓰세요.
- `home: false`: 첫 화면에서 빼고 `/projects/`에만 표시
- `name_en`, `short_en`, `desc_en`: 영어 글에서 쓸 이름과 설명

글 front matter에 `project: blog`처럼 프로젝트 `id`를 적으면, 그 글이 프로젝트의 **관련 글**에 들어가고 글 아래에 **이 글의 프로젝트** 상자가 생깁니다. 첫 화면 최근 글에도 `↳ 프로젝트 이름`이 붙습니다.

현재 프로젝트 목록에는 실제 운영 중인 이 블로그만 있습니다. 새 프로젝트를 추가할 때 실제 사이트 주소와 저장소 주소를 입력하세요.

## 기능 켜기

**댓글 (giscus)**
1. 저장소 **Settings → General → Features**에서 **Discussions**를 켭니다.
2. https://github.com/apps/giscus 에서 앱을 이 저장소에 설치합니다.
3. https://giscus.app/ko 에 저장소 이름을 넣고, 카테고리를 고르면 아래쪽 코드에 `data-repo-id`, `data-category-id` 값이 나옵니다.
4. 그 값을 `_config.yml`의 `giscus` 항목에 붙여 넣습니다. (카테고리는 **Announcements** 형식을 추천합니다. 방문자가 새 토론을 직접 만들지 못해 정리가 쉽습니다.)

**방문 통계 (Cloudflare Web Analytics)**
Cloudflare 대시보드 → Analytics & Logs → Web Analytics에서 사이트를 추가하고, 받은 토큰을 `_config.yml`의 `cloudflare_analytics_token`에 넣습니다.

## 자동으로 처리되는 것

- **GIF → 영상 변환**: 500KB가 넘는 GIF는 배포할 때 MP4로 바뀌어 `<video>`로 표시됩니다. 투명 배경 GIF와 이름에 `.keep.`이 들어간 GIF(`logo.keep.gif`)는 그대로 둡니다. RSS 피드에서는 원본 GIF가 쓰입니다.
- **검색**: 배포할 때 Pagefind가 글 내용으로 검색 색인을 만듭니다. 한국어와 영어 색인이 따로 만들어집니다.
- **공유 미리보기, 사이트맵, RSS**: 글 정보로 자동 생성됩니다.
- **목차**: 소제목이 3개 이상인 글에만 나타납니다. 기준은 `_config.yml`의 `toc_min_headings`에서 바꿀 수 있습니다.

## 영어 자동 번역

한국어 글을 올리면 배포할 때 영어판이 자동으로 만들어집니다. 외부 API 없이 GitHub Actions 안에서 번역 모델(Helsinki-NLP의 OPUS-MT, CC-BY-4.0)을 직접 실행하므로 비용과 API 키가 필요 없습니다.

- 영어 글 주소: `/en/blog/글주소/`, 목록: `/en/blog/`, RSS: `/en/blog/feed.xml`
- 영어 글 맨 위에 **기계 번역 안내**와 원문 링크가 붙고, 한국어 글 제목 아래에는 `English` 링크가 생깁니다.
- 검색엔진에는 두 글이 같은 내용의 다른 언어판이라고 알려줍니다(hreflang). 검색 기능도 언어별로 따로 동작합니다.
- **댓글은 한국어판과 영어판이 함께 씁니다.** 어느 쪽에서 남겨도 양쪽에 보입니다.

**번역되지 않는 것**: 코드 블록, 인라인 코드, 링크·이미지 주소, HTML 태그 안의 내용, 한국어가 없는 줄. 첫 화면 소개와 태그도 한국어로 남습니다.

### 번역 고치기

번역본은 `_en_posts` 폴더에 저장됩니다. Pages CMS의 **영어 번역** 메뉴나 github.dev에서 직접 고칠 수 있습니다.

- 고친 뒤 `translation_locked: true`로 바꾸면 원문이 바뀌어도 덮어쓰지 않습니다. 원문이 바뀌면 Actions 실행 결과에 경고가 뜹니다.
- 사람이 검토를 마쳤다면 `machine_translated: false`로 바꾸세요. 안내 문구가 "Translated from Korean"으로 바뀝니다.
- 다시 기계 번역하고 싶으면 해당 번역 파일을 지우고 푸시하면 됩니다.
- 특정 글을 번역하지 않으려면 원문 front matter에 `translate: false`를 적으세요.

### 용어집

`_data/glossary.yml`에 `한국어: English` 형식으로 적으면 항상 그 단어로 번역합니다. 번역 모델이 자주 틀리는 기술 용어를 여기에 추가하세요. 용어집을 바꿔도 이미 번역된 글은 그대로이니, 다시 번역하려면 해당 번역 파일을 지우세요.

### 품질과 시간

DeepL이나 대형 AI 번역보다는 어색한 문장이 나옵니다. 문장 단위로 번역해서 앞뒤 문맥을 모르고, 생략된 주어나 기술 용어에서 실수가 생길 수 있습니다. 중요한 글은 번역본을 한 번 훑어보고 고친 뒤 잠그는 걸 추천합니다.

바뀐 글이 있을 때만 모델을 실행합니다. 처음에는 모델과 라이브러리를 내려받느라 배포가 5분 정도 더 걸리고, 이후에는 모델을 캐시해서 글 한 편당 1~2분 정도입니다. 나중에 번역 품질을 높이고 싶으면 `scripts/translate_posts.py`의 `Translator`만 다른 엔진(API 등)으로 바꾸면 됩니다.

## 문단 댓글

글의 문단마다 댓글 스레드를 달 수 있습니다. 댓글은 모두 giscus(GitHub Discussions)에 저장되므로, 글 아래 댓글창은 **전체 댓글 기록**이 되고 문단 옆에는 그 문단에 달린 댓글만 모여서 보입니다. 한국어판과 영어판은 문단 댓글도 함께 씁니다.

**읽기**: 댓글이 있는 문단 오른쪽에 개수 표시가 나타납니다. 누르면 넓은 화면(1280px 이상이고 옆에 공간이 있을 때)에서는 문단 옆에, 그보다 좁으면 화면 아래에서 스레드가 열립니다. 블로그 주인의 답글에는 "작성자" 표시가 붙습니다.

**쓰기**: 문단에 마우스를 올리면(휴대폰은 문단을 누르면) 오른쪽에 `+` 버튼이 나타납니다. **이 문단에 댓글 쓰기**를 누르면 문단 링크와 인용문이 복사되고 아래 댓글창으로 이동합니다. 붙여 넣고 이어서 쓰면 됩니다. giscus 입력창에 내용을 미리 채울 수 없어서 붙여 넣는 단계가 필요합니다.

**반영 시간**: 정적 사이트라 댓글이 달리면 Actions가 사이트를 다시 빌드해야 문단 옆에 나타납니다. 보통 2~3분 걸립니다. 아래 댓글창에는 바로 보입니다.

**글을 고쳤을 때**: 문단 표시는 문단 내용으로 만들어서, 문단을 고치면 표시가 바뀝니다. 그래도 댓글에 인용된 문장과 가장 비슷한 문단을 찾아 다시 붙여줍니다. 많이 바뀌어서 찾지 못한 댓글은 문단 옆에서 사라지지만 아래 댓글창에는 그대로 남습니다.

댓글 첫 줄에 문단 링크가 없는 일반 댓글은 아래 댓글창에만 보입니다.

## 사진 메타데이터 제거

사진의 위치(GPS), 촬영 기기, 촬영 시각 같은 정보는 두 곳에서 자동으로 지워집니다. 사진 방향과 색상 정보는 남깁니다.

- **배포할 때 (항상 동작)**: `assets` 폴더의 사진을 검사해 정보를 지우고, 정리된 사진을 저장소에 다시 저장합니다. Pages CMS로 올린 사진도 여기서 처리됩니다. 처리한 파일은 Actions 실행 결과의 요약에 표시됩니다.
- **내 컴퓨터에서 커밋할 때 (선택)**: `exiftool`을 설치하고(`brew install exiftool`) 저장소 폴더에서 `bash scripts/install-hooks.sh`를 한 번 실행하면, 커밋하기 전에 지워져서 원본이 아예 올라가지 않습니다.

**배포할 때 지우는 방식은 원본이 커밋 기록에 남습니다.** 사이트에는 정리된 사진만 올라가지만, 저장소의 이전 커밋을 열면 원본을 받을 수 있습니다. 가장 확실한 방법은 처음부터 위치 정보가 없는 사진을 쓰는 것입니다.

- iPhone: 사진 공유 화면 위쪽의 **옵션**에서 **위치**를 끄고 공유하거나, 설정 → 개인정보 보호 → 위치 서비스 → 카메라를 **안 함**으로
- Android: 카메라 앱 설정에서 **위치 태그**를 끄기

### 커밋 기록에서 지우기

집 근처처럼 민감한 사진의 원본이 이미 올라갔다면, `git filter-repo`로 기록에서 그 파일을 지우고 강제로 push해야 합니다. 이미 포크나 복제된 곳에는 남을 수 있으니, 이런 일이 없도록 위의 휴대폰 설정이나 커밋 훅을 쓰는 걸 추천합니다.

## 월간 보안 점검

매월 1일 오전 9시에 **보안 점검 이슈**가 자동으로 만들어지고 나에게 할당되어 알림이 옵니다. 이슈에는 다음이 들어 있습니다.

- **자동 확인**: 지난 한 달 동안 이 저장소에 커밋한 계정 목록. 본인과 배포 봇이 아닌 계정은 ⚠️로 표시됩니다. 본인 커밋인데 ⚠️가 붙는다면, git에 설정한 이메일이 GitHub 계정에 등록되지 않은 경우입니다.
- **직접 확인할 체크리스트**: 설치한 앱, 승인한 앱, 토큰, SSH 키, 로그인 기록, 협업자, 웹훅 등의 설정 페이지 링크

설치된 앱 목록은 Actions의 기본 권한으로는 자동으로 읽을 수 없어서 체크리스트로 확인하게 했습니다. 읽으려면 계정 전체 권한을 가진 토큰을 저장소에 넣어야 하는데, 그 토큰 자체가 더 큰 위험이 됩니다.

**저장소에 60일 동안 아무 활동이 없으면 GitHub가 예약 실행을 자동으로 멈춥니다.** 멈추면 GitHub가 이메일로 알려주니, Actions 탭에서 다시 켜거나 새 글을 올리면 됩니다. Actions 탭에서 **월간 보안 점검 → Run workflow**를 누르면 언제든 바로 실행할 수 있습니다.

## 내 컴퓨터에서 미리 보기 (선택)

Ruby를 설치한 뒤:

```bash
bundle install
bundle exec jekyll serve
```

`http://localhost:4000`에서 볼 수 있습니다. 검색까지 확인하려면 `bundle exec jekyll build && npx pagefind --site _site --serve`를 실행하세요.

## 도메인을 연결하려면

Settings → Pages → Custom domain에 도메인을 넣고, 도메인 업체에서 DNS를 GitHub Pages로 연결합니다. 그 뒤 `_config.yml`의 `url`을 새 주소로 바꾸세요.
